3. Metadata issue - fixed
File: `lib/elixir/src/elixir_bitstring.erl:54-64`
In the non-`::` bitstring-segment branch, the recursive call passes `Meta` instead of `BitstrMeta`:
`expand(Meta, Fun, T, EAcc, {SS, OriginalS}, ES, Alignment, RequireSize)`.
That changes the fallback metadata for all following segments from the enclosing bitstring metadata to the current segment metadata. As a result, any later segment without its own metadata inherits the previous segment's line/column information, so inferred specs and diagnostics can point at the wrong source location.
Reasoning path:
For `<<x, "a">>`, the first segment `x` has its own metadata, so `Meta = extract_meta(H, BitstrMeta)` becomes `x`'s metadata. Line 64 then stores that as the next `BitstrMeta`. The following literal segment `"a"` has no segment metadata, so `extract_meta/2` falls back to `x`'s metadata instead of the enclosing bitstring metadata. Upstream keeps `BitstrMeta` in the recursive call, which preserves correct fallback metadata.
